## Concrete driver and authority

`scripts/floor1/v01-native-boundary-runtime.h` binds the original-batch adapter to the installed mGBA0.10.5 `ARMCore`, `GBA.timing`, `frameCounter`, `getKeys`, `cpu->irqh.processEvents` and `ARMRun` APIs. The generated host replaces its sole frame-driving call. Original input setters/controller body, every completed-frame capture and graphics/readiness/lifecycle gates remain. The 36000-frame guard is checked before driving another frame.

The outer frame/time guard retains `VIDEO_TOTAL_LENGTH + VIDEO_HORIZONTAL_LENGTH` (282128 cycles). The inner instruction batch runs only while `cycles < nextEvent`; it passively checks the hardware breakpoint and calls installed `ARMRun` for the next original instruction. A due event is dispatched directly through the installed handler, then the original outer guard is rechecked. Calling `ARMRun` while an event is due is prohibited: that API processes the event and then executes an instruction. Mode transitions force event processing through native scheduling. There is no stepping after the frame loop, no scheduler/CPU restoration and no key changes in the binding. A timeout that fails to complete exactly one video frame stops118 rather than inventing a completed frame.

Both exact ELFs resolve private `L:main.o:WaitForVBlank` entry080008ac, opcodeb500, unique direct AgbMain BL080004ba and Thumb callerLR080004bf. ELF32 STT_FUNC scope/extent and consecutive PlayTimeCounter_Update/MapMusicMain/WaitForVBlank calls are verified during preparation. Authority metadata and exact ELF/symbol/source/library hashes are frozen in the existing preparation identity; old preparations cannot execute this changed host. Entry opcode is rechecked from the loaded build before attachment. The existing exclusive-claim and baseline-before-candidate gates remain.

Custom hardware-only debugger attachment uses a per-instance passive platform hook. It avoids default `ARMDebuggerEnter`'s `nextEvent=cycles` write. A hit must have the exact hardware point ID/address, raw PCentry+2, caller LR, prefetched push opcode, Thumb execution, SYSTEM privilege/CPSR, nonhalted CPU and no due event. IRQ callbacks also enter SYSTEM, so mode alone cannot qualify them. Whole ARMCore equality surrounds every hardware observation. Unknown authority stops115 before the next instruction.

## Complete snapshots and stream

`bv_snapshot` is the original complete reader extracted from the old raw-frame comparer: all600 party bytes,352 BattleMons bytes,300 flag bytes,1272 owned/resource bytes, complete scalar/control tail and zero padding, exactly2560 bytes. Only the existing verified native controller symbol identities canonicalise build-dependent addresses. No additional normalisation, byte mask, ignored offset or decrypt-phase exception exists. Both matching records must also have native encrypted-party checksums and no BadEgg (stop116).

The new private `native-boundary-trace.bin` stream is incompatible with historical raw-frame `state-trace.bin`. It never consumes or changes an old trace. Each boundary writes/matches a29-byte typed metadata record and all2560 bytes; each completed video frame writes/matches a29-byte F record, including a zero-boundary frame; finish writes/matches E and rejects trailing data. All records include exact64-bit ordinal, video epoch, input epoch, boundary count, absolute installed frame counter and input keys. Missing/duplicate/reordered boundaries, different counts/epochs/keys or missing records stop117. There is no candidate alignment search or padding of truncated references. Native boundary count/order are exact, not inferred from video frame count.

`visual ready` and `visual finish` require a complete boundary from the current video/input epoch. A zero-boundary frame supplies no fresh checkpoint authority; the host does not execute extra instructions to obtain one. Successful finish still requires all existing native retirement/field, pose/palette/warning/swap/resource gates and exact stream end. First failure is sticky in the binding and the host exits immediately. Full failed snapshot records remain local mode0600; existing public-safe byte/CPU diagnostics and resource/key redaction are retained. Generated host is compile-tested only in this increment.

## Installed evidence and limits

Run `scripts/test-f1-v01-native-runtime.py --output <fresh-directory>` in pinned `dcc-party-resource`. It compiles the full host without invoking it and runs actual installed-library synthetic instruction fixtures. No ROM/Save is loaded and no game/reset/gameplay capture/exclusive claim occurs. The fixture initialises empty GBA cores, supplies a synthetic instruction region/EWRAM and schedules synthetic events through installed mTiming/GBA processing. Its frame counters are synthetic fixture events, not rendered game frames.

Each fixture variant compares installed `core->runFrame`/`ARMRunLoop` against the binding:12 Thumb/arithmetic/BX ARM↔Thumb/due-event/IRQ/MSR-to-SYSTEM combinations, due frame-ending event with zero further instructions, eight fixed input/video epochs and a long original batch exceeding the timeout guard. CPU registers/CPSR/SPSR/banked state/prefetch/operands/cycles/nextEvent, RAM, timing, bus, keys and event ordering/lateness/frame counts match. One variant uses register-buffer snapshots; the second includes the generated production host and binds the actual complete snapshot reader to installed native bus APIs, with synthetic EWRAM covering every domain.

Actual installed hardware-stream positives and negatives cover four ordered snapshots, all29 metadata bytes, every2560 snapshot byte, zero-count/stale-checkpoint rejection, missing/duplicate/reordered boundaries, missing/corrupt frame counts, trailing finish data, BadEgg/checksum, truncation, sticky first STOP and a real IRQ callback reaching exact entry in Thumb SYSTEM with a foreign LR. The earlier generic scheduler-model fixtures and graphics/lifecycle/native ABI/symbol/diagnostic regressions passed separately; those model tests are not represented as interpreter executions.

Two new development failures are retained separately in safe history: buffered stream truncation was overwritten by pending stdio output (flush before truncate); the complete-reader fixture initially used byte offsets on a uint32_t EWRAM pointer and an unused variable (byte view and scoped declaration corrected). Neither is gameplay or a replacement for any old failure record.
